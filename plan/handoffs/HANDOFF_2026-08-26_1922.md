## The two suspects

**Suspect 1 — the new video id never arrives.**
The YouTube search is slow or fails, so `youtubeVideoId` stays empty. The live effect
returns early at `YouTubeBackground.jsx:155`. The old iframe keeps playing. It only dims
to 20% opacity (`liveFade`, `YouTubeBackground.jsx:219-226`), so it still looks like the
old video is running.

**Suspect 2 — the id arrives but the iframe ignores it.**
The live player is built with `loop: 1` and `playlist: videoId`
(`YouTubeBackground.jsx:174-176`). That makes a one-item playlist out of the **first**
video ever loaded. Later `loadVideoById()` calls fight with that playlist and YouTube can
snap back to the original. Note the `ENDED` handler at `YouTubeBackground.jsx:187-190`
already loops by hand (`seekTo(0)` + `playVideo()`), so `loop`/`playlist` is redundant.

Suspect 2 matches the user's wording better ("the *original* video").

## How to read the logs

| What you see | Verdict |
|---|---|
| No `[VIDSWAP] search finished` line for the new song | **Suspect 1** — backend never found a video |
| `search finished` fires but no `[VIDSWAP] videoId changed` | Frontend is not receiving the update — new third suspect |
| `calling loadVideoById` fires but `live state=... actually='<old id>'` | **Suspect 2** — the loop/playlist conflict |

## Decisions locked in this session

- Log first, fix second. Guessing wrong costs a whole Pandora test cycle, and the test
  can only be run by the user (Claude cannot reproduce it — see `project_test_flow`).
- Do not fix Suspect 2 blind. It is a 2-line delete and safe, but it is worthless if the
  real cause is Suspect 1.
- No behaviour changes were made. The one structural edit — splitting
  `if (isPlayerMode || !videoId) return;` into two branches — exists only so the empty
  case can log. It is behaviour-neutral.
- The `[VIDSWAP] no videoId yet` log is guarded by `loggedEmptyForRef`
  (`YouTubeBackground.jsx:88`) because the live effect re-runs on every render —
  `onLiveVideoError` is an inline arrow in `App.jsx:447`, so its identity changes every
  time. Without the guard that line floods the console.
