## TL;DR

In live (capture) mode the bottom card now shows the video save state: dark = still looking,
yellow = downloading, green = on disk (safe to skip on Pandora), red = download failed. The
user saw green work and said "good enough for now"; yellow and red are built but not yet seen
live. The mood-sequencing work from the prior handoff is untouched and is still the next job.

## What was done this session

  `GET /captured/{video_id}`. **Wrong goal** — the user wants a skip signal while capturing,
  and signatures/moods only come from batch scripts, so a new song would never go green.
- Second try (`ca483b1`): green in live mode only, when `media.localVideoUrl` is set. The
  `/captured` endpoint was removed. User confirmed: "I see the green."

  reported as `failed` (it used to vanish). Card CSS classes `.saving` / `.save-failed` /
  `.captured` in `frontend/src/App.css`; mapping in `frontend/src/components/PlayerControls.jsx`.
- README: new "Capture card colors (live mode)" section under Local Video Cache.

## Decisions locked in this session

- **Green = video on disk, nothing else.** Skipping early loses the video because the YouTube
  search aborts on track change (`[STALE] Aborting YouTube search`). Signature and mood are
  made later from the file, so they must not gate the skip.
- **Capture mode only.** Player (playback) mode never colors the card — user said so.
- **No YouTube video found → card stays dark.** Nothing to save.
