## TL;DR

Two small player fixes are committed and built: the "Up next" label no longer lies, and the
YouTube pause button no longer sits in the middle of the screen. The user loves Rando and
asked how it picks songs and how to steer it later; they said "let me think" and have not
decided anything yet. Nothing is in flight. Next: wait for the user's test report and their
steering decision, then pick the next backlog item.

## What was done this session

- Explained how Rando picks songs (`backend/radio.py`): whole `tracks` table (~620 songs),
  weighted by decaying genre mood, 18% wildcard, novelty (90-day horizon), taste (finishes,
  skips, thumbs), and a 100-song repeat guard. No code change.
- Found and fixed the "Up next shows one band, another plays" bug. Cause: `nextPlayerTrack`
  in `frontend/src/App.jsx` used `(playerIndex + 1) % queue.length`, so at the end of the
  queue it wrapped to queue[0] (the first song of the session) while Rando appended a fresh
  pick. Now it scans forward for the next unheard song and never wraps; when there is none
  and Rando is on, `PlayerControls.jsx` shows "Up next: Rando picks when this one ends".
  Commit `7c26763`.
- Removed the center "pause" icon. It is YouTube's own large play button drawn inside the
  iframe; nothing outside can style it. `YouTubeBackground.jsx` now tracks `PAUSED` from
  `onStateChange` and sets the player layer opacity to 0 while paused (existing 0.3s
  transition). Video fades back in on play. Commit `5ade86f`.
- Listed the backlog for the user (`plan/BACKLOG.md`): Song signatures (NEXT UP), Pandora
  catalog harvest (only item with a deadline), Discovery, Playlists + mood steering.

## Decisions locked in this session

- Hide the YouTube pause button by fading the whole player layer, not by covering it. The
  user was told this loses the frozen frame and offered a dark-cover alternative; they have
  not objected yet.
- The old live-video-swap bug from the prior handoff was fixed in commit `39f596c` before
  this session (WinRT media session restored, `[VIDSWAP]` logging kept).
