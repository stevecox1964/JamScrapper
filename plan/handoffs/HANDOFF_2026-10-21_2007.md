## What was done this session

- Read `backend/data/client.log`. The last song (Jim Funk – Ribcage Rumble, video `HQq91RgZJyw`) hit YouTube error 150 (embed blocked). The flip to the slideshow worked, but the slideshow had about 0–1 images.
- `backend/server.py` `fetch_artist_images()`: after TheAudioDB and Wikipedia, it now always adds:
  - Deezer artist photo (`picture_xl`). It is used only when the artist name matches exactly.
  - iTunes album covers at 600x600. Up to 10, exact artist-name match only.
  - Wikimedia Commons photos found by `"<artist>" filetype:bitmap`. Up to 12, at 1000px wide.
  - It logs `[IMG] <artist>: N images`.
- Tested the function on its own: Jim Funk 10 images, The Cars 24, Duran Duran 24.
- README: added the image sources to the AI Video section and the Artist Profiles row. Removed the "expand image pool" item from the future list.

## Decisions locked in this session

- Keep the existing `SyntheticVideo.jsx` slideshow. Fix the gap by giving it more images, not by building a new view.
- No API keys. Use free sources only. This fits the self-reliance rule (outside services for cataloging only).

## Open questions

- Wikimedia Commons search can return pictures that are not the band (for example, a place with the same name). This was not seen in the test. Watch for it.
- Image fetches run one after another, with a 5 s timeout each. The worst case is about 25 s before images show. It is non-blocking, so it is OK for now.
